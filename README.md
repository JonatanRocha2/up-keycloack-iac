# DefensePoint Cloud Engineer Assessment

This project automates the provisioning of AWS infrastructure using Terraform and configures a Keycloak instance via Docker Compose using Ansible.

## 🚀 Provisioning & Configuration

### 1. Infrastructure Provisioning (Terraform)
This step provisions the AWS infrastructure, including an Ubuntu 20.04 EC2 instance and a Security Group configured to allow inbound traffic on ports 22 (SSH), 8080 (Keycloak HTTP), and 443 (HTTPS).

```bash
cd terraform
terraform init
terraform apply -var="key_name=your_aws_ssh_key" -auto-approve
```

[!NOTE]
Take note of the `instance_public_ip` generated in the terminal output, as it will be required for the next step.

2. Service Configuration (Ansible)
This step configures the host, installs Docker and the Docker Compose plugin, and deploys the Keycloak stack (with PostgreSQL) securely. Sensitive credentials are encrypted using Ansible Vault.

Update the ansible/inventory.ini file with the public IP generated by Terraform.

Execute the configuration playbook:

```bash
cd ../ansible
ansible-playbook -i inventory.ini playbook.yaml --ask-vault-pass
```

[!IMPORTANT]
When prompted for the vault password, please use: <ENTER_YOUR_PASSWORD_HERE> (Note: Provide the password you used to encrypt the vault so the evaluator can run it).

### 🧠 Assumptions & Challenges

- Free Tier Constraints: Opted for a t3.micro instance. To ensure stability within the 1GB RAM limit, Keycloak and PostgreSQL were deployed in a shared Docker network using resource-conscious defaults.

- Security: Sensitive data (Database and Keycloak Admin passwords) were strictly managed and encrypted using ansible-vault, avoiding plain-text exposure in the repository.

- Networking: The AWS Security Group was explicitly configured to allow ingress on ports 22 (SSH), 8080 (Keycloak HTTP), and 443 (HTTPS) as requested.

## 💡 Future Improvements (Production Readiness)

While the current setup successfully demonstrates an IaC deployment approach within AWS Free Tier constraints, moving this to a production environment would require architectural enhancements. If given more time, I would implement the following:

* **HTTPS & Load Balancing:**
  Currently, Keycloak is exposed directly on port `8080`. I would introduce an AWS Application Load Balancer (ALB) paired with AWS Certificate Manager (ACM) to handle TLS/SSL termination, ensuring secure access via standard HTTPS (port `443`).
* **Remote Terraform State:**
  To support team collaboration and CI/CD automation seamlessly, the local Terraform state (`.tfstate`) should be migrated to an Amazon S3 backend with DynamoDB state locking to prevent concurrent modification issues.
* **Production-Grade Keycloak Configuration:**
  Transition Keycloak from development mode (`start-dev`) to a fully optimized production build (`start`). This includes configuring strict hostname providers, fine-tuning the Infinispan distributed cache, and implementing comprehensive observability (metrics and centralized logging).
